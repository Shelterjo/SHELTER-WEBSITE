## 1. النطاق والمبدأ
- **ما هو:** نظام توظيف أصلي داخل **SHELTER Website + SHELTER Owner Dashboard**. البيانات تملكها SHELTER وتبقى على Cloudways.
- **ممنوع:**
  - HubSpot وGoogle Forms وAirtable وأي CRM خارجي.
  - أي قاعدة بيانات على جهاز الـOwner أو مرتبطة بجهاز العمل.
  - **Falcon أو قواعد بياناته.**
  - أي خدمة خارجية بلا موافقة مسبقة.
- **المسار:** موقع عام ← HTTPS ← SHELTER Backend ← قاعدة بيانات خاصة على Cloudways + تخزين خاص للمرفقات ← Owner Dashboard.

## 4. هيكل النموذج وتجربته
- **المجموعات:** البيانات الشخصية · السكن · المؤهل والخبرة · معلومات العمل · المرفقات · الإقرار.
- **صفحة واحدة أم خطوات قصيرة:** قرار تقني مفوّض للاختبار (M28 §67). النتيجة والدليل في [`careers/wireframes/README.md`](careers/wireframes/README.md).
- **الشكل:** Premium · Minimal · Clean · Fast · سهل جدًا · عربي أولًا · زوايا مستديرة · Responsive. **ليس** نموذجًا حكوميًا أو HubSpot أو Bootstrap عاديًا. **الوضوح قبل الجمال.**
- **الأداء:**
  - لا مكتبات الـDashboard في صفحة Careers.
  - الرفع تدريجي مع نسبة تقدم.
  - تحليل المستندات غير متزامن.
- **حالات الفشل المصممة:**
  - خطأ تحقق، وفشل رفع، وامتلاء التخزين، وتوقف قاعدة البيانات.
  - إرسال مكرر، وملف غير صالح، وملف خطر، وتجاوز الحد التقني.
  - انتهاء المهلة، وعدم اكتشاف الـCV، وانقطاع الشبكة.
  - **لا تُفقد المدخلات بسبب فشل ملف واحد.**

## 5. بعد الإرسال
1. **التحقق والرقم:**
   - تحقق Server-side إلزامي.
   - رقم طلب فريد يُولد في الخادم: `JOB-2026-00125` (`RECRUITMENT-DATA-MODEL.md` §3).
2. **صفحة النجاح** (عربي فقط):
   - تم استلام طلب التوظيف بنجاح.
   - رقم الطلب.
   - SHELTER ستتواصل عند الحاجة.
   - زر العودة للموقع.
   - **لا بيانات حساسة في الـURL.**
3. **لا Email ولا WhatsApp تلقائي.**
4. **متابعة طلب التوظيف:**
   - بلا حساب، برقم الطلب + رقم الهاتف فقط.
   - Rate limit، وحماية من الـEnumeration، وأخطاء عامة.
   - تعرض **الحالة العامة فقط** (`RECRUITMENT-PUBLIC-STATUS-MAPPING.md`).
5. **لا تعديل من المتقدم بعد الإرسال.** التصحيح الإداري للـOwner فقط + Audit.
6. **التقديم المتكرر مسموح:**
   - ربط بالطلبات السابقة بالهاتف أو الرقم الوطني أو الوثيقة أو البريد، و**بلا دمج**.
   - كل طلب مستقل برقمه وتاريخه وحالته ومرفقاته وسجله.
   - الـDashboard يعرض "متقدم سابق — لديه X طلبات".

## 6. وحدة التوظيف في الـOwner Dashboard (Owner فقط)
**الهيكل:** التوظيف ← نظرة عامة · الطلبات · المقابلات · الأرشيف · الفلاتر المحفوظة · الإعدادات. يُعدّل إذا كان أفضل لـUX دون تغيير المتطلبات.

| الميزة | المتطلب المعتمد |
|---|---|
| نظرة عامة | 8 بطاقات قابلة للضغط تفتح الطلبات مفلترة:<br>- الجديدة، والإجمالي، وقيد المراجعة، والمرشحون للمقابلة.<br>- تمت المقابلة، والمقبولون، والمرفوضون، والمؤرشفون.<br>تشغيلية أولًا، **بلا رسوم بيانية غير ضرورية** |
| الفترة | الافتراضي **هذا الشهر**. الخيارات: اليوم · آخر 7 أيام · آخر 30 يوم · هذا الشهر · كل الوقت. **بلا نسب مقارنة** |
| "جديد" | حالة القراءة منفصلة عن حالة الطلب. فتح الطلب أول مرة يعلّمه مقروءًا **ولا يغيّر حالته** |
| الإشعارات | داخل الـDashboard فقط: شارة على التوظيف + عدّاد + قسم "يحتاج انتباه/طلبات جديدة". **لا Email ولا WhatsApp** |
| الجدول | الأعمدة: الاسم · الوظيفة · المدينة · سنوات الخبرة · الراتب المتوقع · تاريخ التقديم · الحالة. **الأحدث أولًا** |
| الفرز | الأحدث/الأقدم · الراتب الأعلى/الأقل · الخبرة الأعلى/الأقل |
| البحث | بحث سريع **أثناء الكتابة** (Debounce) في: الاسم · الهاتف · البريد · رقم الطلب · الوظيفة · المدينة |
| الفلاتر | الاسم · الهاتف · الوظيفة · المدينة · المؤهل · الخبرة · الحالة · الجنس · الجنسية · تاريخ التقديم. **مجتمعة** |
| الفلاتر المحفوظة | حفظ باسم (مثل "مرشحين محاسبة إربد") وفتح بضغطة |
| الأعمدة | إظهار/إخفاء · سحب وإفلات للترتيب · إعادة الافتراضي · **تُحفظ** |
| الكثافة | Comfortable / Compact · تُحفظ |
| حجم الصفحة | 25 · 50 · 100. **الافتراضي 50 على الديسكتوب.** يُحفظ آخر اختيار |
| الترقيم | تقليدي: السابق · التالي · أرقام الصفحات · الانتقال لرقم. **لا Infinite Scroll** |
| الموبايل | **لا جدول ديسكتوب مضغوط:** بطاقات أو جدول متكيف |
| العرض السريع | Side panel: الاسم · الوظيفة · المدينة · الخبرة · الراتب · الحالة · الهاتف · البريد · ملخص المرفقات · تغيير الحالة |
| الصفحة الكاملة | كل البيانات بترتيب واضح:<br>- رقم الطلب، والوقت، والحالة، وحالة القراءة.<br>- الـCV، والمرفقات، والملاحظات، والمقابلة.<br>- الطلبات السابقة، وتاريخ الحالة، والـAudit، وسجل الموافقة.<br>**ليست تفريغًا لحقول قاعدة البيانات** |
| الملاحظات الداخلية | متعددة ومستقلة (المحتوى + الكاتب + الوقت). لا Overwrite. أي تعديل أو حذف مسجل |
| المقابلة | التاريخ · الوقت · المكان (قائمة فقط: SHELTER COFFEE DRIVE / SHELTER COFFEE HOUSE، قابلة للإدارة) · ملاحظات داخلية |
| **لا تقييم** | لا Scores، ولا نجوم، ولا تقييم مقابلة، ولا AI ranking |
| الإجراءات الجماعية | تغيير الحالة (بتأكيد واحد واضح: "أنت على وشك تغيير حالة 20 طلبًا إلى قيد المراجعة.") · أرشفة · تصدير · تنزيل المرفقات. **لا حذف نهائي جماعي** |
| الأرشفة والحذف | نشط ← أرشيف ← حذف نهائي:<br>- Owner فقط، بتأكيد قوي، وTombstone.<br>- **لا حذف تلقائي أبدًا.**<br>- "Last Updated" وتنبيه للطلبات القديمة **بلا حذف** |
| التصدير | Excel · CSV · PDF:<br>- الكل، أو المفلتر، أو المحدد، أو حسب الحالة، أو الفترة، أو الوظيفة.<br>- **الهوية مقنّعة افتراضيًا.** الكاملة باختيار صريح وتدفق آمن |
| تنزيل المرفقات | إجراء منفصل يجمعها في ZIP للطلبات المحددة. Owner فقط + Audit |
| سجل التدقيق | كل العمليات (القائمة في `RECRUITMENT-DATA-MODEL.md` §2.14): الفاعل · الإجراء · الهدف · الوقت · قبل · بعد · السياق. **بلا محتوى ملفات حساسة** |

## 9. Definition of Done (M28 §79)
**المبدأ:** النظام لا يُعتبر منتهيًا لأن النموذج يعمل.

**DONE يعني:**
- **النموذج والبيانات:**
  - نموذج عام يعمل، بتجربة عربية صحيحة، Responsive وآمن.
  - البيانات محفوظة على Cloudways.
  - لا HubSpot ولا قاعدة محلية.
  - الملفات خاصة.
- **وظائف المتقدم:** اكتشاف الـCV يعمل، والمتابعة تعمل.
- **الـOwner Dashboard:**
  - يعمل، والصلاحية للـOwner فقط متحقق منها.
  - البحث والفلاتر والتصدير والمقابلات والملاحظات والـAudit والأرشفة والحذف تعمل.
- **التحقق:**
  - النسخ الاحتياطية مراجعة.
  - Accessibility مُختبرة.
  - Playwright ناجح.
  - أمان الإنتاج مراجَع.
