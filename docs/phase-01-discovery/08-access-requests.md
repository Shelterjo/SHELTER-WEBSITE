# 08 — Access & Permission Requests (طلبات الصلاحيات)

> **آخر تحديث:** 2026-10-01
> **القواعد:**
> - كل الطلبات **Read-only**. لا نطلب Write access لأي خدمة في هذه المرحلة.
> - **لا تُرسل أي كلمة مرور أو Token أو API Key في المحادثة.** المفاتيح توضع في إعدادات بيئة العمل (Environment settings) فقط، ونخبرك باسم المتغير الذي سنقرأه. المفاتيح الجديدة تُقرأ في **جلسة جديدة**، وليس في الجلسة الحالية.
> - لا يتم أي تغيير على Production. أي تغيير مستقبلي يمر بـStaging ثم موافقتك.
> - الحالة: `REQUESTED` (مطلوب) · `GRANTED` (مُنح) · `DECLINED` (مرفوض) · `NOT NEEDED` (غير مطلوب الآن)

## AC-01 — إعدادات شبكة بيئة العمل (Claude Code Environment → Network access)
1. **الخدمة:** إعداد بيئة العمل السحابية التي أعمل منها (ليست خدمة خارجية).
2. **لماذا:** الشبكة تحجب `shelterjo.com` حاليًا، ولهذا لم نقرأ النصوص والصور والـNavigation والـFooter والأداء.
3. **المستوى:** Read-only. طلبات `GET` عادية للصفحات العامة فقط، مثل أي زائر.
4. **ماذا سنفحص:**
   - Crawl كامل للصفحات العامة.
   - النصوص الحرفية، والـHeadings، والـMeta، والـCanonical، والـSchema.
   - الصور والـAlt، والـRedirects وصفحة 404.
   - السكربتات الموجودة (GA4/GTM/Pixel)، والـHeaders (HSTS/CSP).
   - Lighthouse على الموبايل والديسكتوب، وفحص Accessibility.
   - Playwright لرحلة المستخدم.
   - نفس الفحص لـ`shop.shelterjo.com`.
5. **المخاطرة على Production:**
   - لا تغيير إطلاقًا.
   - الحمل خفيف: بضع مئات من الطلبات ببطء.
   - احتمال ضعيف أن يعرض Cloudflare تحديًا (Challenge) للزاحف. لن نغيّر أي إعداد لتجاوزه، وسنخبرك إذا حدث.
- **كيف تمنحه:** قائمة الـEnvironment في أعلى الجلسة ← Edit ← Network access ← أضف `shelterjo.com` و`www.shelterjo.com` و`shop.shelterjo.com` إلى الـAllowed domains.

## AC-02 — Google Search Console
1. **الخدمة:** Google Search Console لـ`shelterjo.com`.
2. **لماذا:** أرقام Semrush تقديرية فقط. Search Console هو المصدر الحقيقي للنقرات والظهور والصفحات المفهرسة والروابط الخارجية، وهو الأساس لخريطة الـ301.
3. **المستوى:** Read-only. الصلاحية في Search Console اسمها **Restricted**.
4. **ماذا سنفحص:**
   - تقارير Performance لـ16 شهرًا (الكلمات والصفحات والدول والأجهزة).
   - الصفحات المفهرسة وغير المفهرسة وأسبابها.
   - الـSitemaps، وCore Web Vitals.
   - تقرير Links، الذي يعوّض قائمة الروابط التي لم نحصل عليها من Semrush.
   - التحسينات والـRich results.
5. **المخاطرة:** لا شيء. الصلاحية Restricted لا تسمح بأي تغيير.
- **كيف تمنحه (اختر واحدًا):**
  - **A (موصى به):** تصدير التقارير من Search Console (Export → CSV أو Google Sheets) ورفعها هنا أو في Google Drive.
  - **B:** Service Account للقراءة عبر الـAPI. يتطلب إنشاءه في Google Cloud، ثم إضافة بريده كمستخدم Restricted في Search Console، ثم وضع ملف المفتاح كمتغير في إعدادات بيئة العمل. سنرسل لك الخطوات بالتفصيل إذا اخترت B.
  - **C:** إذا كان Search Console مربوطًا مسبقًا في Supermetrics، نقرأ منه (انظر AC-04).

## AC-03 — Google Business Profile (فرع الدرايف + فرع سيتي سنتر)
1. **الخدمة:** ملفا النشاط التجاري على Google Maps.
2. **لماذا:** هما المصدر الذي يراه أغلب العملاء. نحتاج مطابقة الاسم والعنوان والهاتف والساعات والتصنيفات ورابط الموقع بين Google والموقع الجديد. لا نستطيع رؤيتهما من بيئة العمل.
3. **المستوى:** معلومات فقط. **لا نطلب Manager ولا Owner.**
4. **ماذا سنفحص:**
   - الاسم كما هو مكتوب، والتصنيف الأساسي والثانوي، والعنوان، والهاتف، والساعات (العادية والخاصة).
   - رابط الموقع، والخصائص (Attributes)، والوصف.
   - عدد التقييمات والمتوسط، وعدد الصور.
5. **المخاطرة:** لا شيء.
- **كيف تمنحه:** أرسل رابط كل فرع، مع لقطات شاشة لصفحة "Edit profile" (المعلومات الأساسية، الساعات، الرابط، التصنيفات). أو صدّرها إن أمكن.

## AC-04 — Supermetrics (متصل أصلًا بهذه الجلسة)
1. **الخدمة:** Supermetrics Marketing Analytics، وهو Connector مرتبط بحسابك ومفعّل في هذه الجلسة.
2. **لماذا:** إذا كانت حسابات Google Search Console أو GA4 أو Google Business Profile أو Meta مربوطة فيه، نقرأ البيانات مباشرة بدون إنشاء صلاحيات جديدة.
3. **المستوى:** Read-only. استعلامات قراءة فقط.
4. **ماذا سنفحص:**
   - **أولًا:** أي مصادر بيانات مربوطة. هذا استعلام عن الحالة فقط ولا يقرأ أي بيانات.
   - **ثم بموافقتك:** تقارير Search Console وGA4 لآخر 16 شهرًا، وبيانات Google Business Profile إن وُجدت.
5. **المخاطرة:** لا تغيير. قد تستهلك الاستعلامات جزءًا من حصة حسابك في Supermetrics إن كانت محدودة.
- **كيف تمنحه:** اكتب "موافق على Supermetrics قراءة فقط".

## AC-05 — GA4 + Google Tag Manager
1. **الخدمة:** Google Analytics 4 وGoogle Tag Manager، إن وُجدا.
2. **لماذا:** نبني خطة القياس (Measurement Plan) على ما هو موجود، ولا نكرر Tags، ولا نكسر التتبع عند الإطلاق.
3. **المستوى:** Read-only. **Viewer** في GA4، و**Read** في GTM.
4. **ماذا سنفحص:**
   - مصادر الزيارات، والصفحات الأكثر زيارة، والأحداث (Events) الحالية، والتحويلات.
   - قائمة الـTags والـTriggers في GTM.
5. **المخاطرة:** لا شيء بهذه المستويات.
- **كيف تمنحه:** أرسل الـMeasurement ID والـContainer ID أولًا. نفس خيارات AC-02 (تصدير، أو Service Account، أو Supermetrics). للـGTM: تصدير الـContainer (Admin → Export Container) كملف JSON يكفي.

## AC-06 — Cloudflare (Zone settings, DNS, Rules)
1. **الخدمة:** حساب Cloudflare الخاص بـ`shelterjo.com`. ملاحظة: الـConnector المتصل بالجلسة (Cloudflare Developer Platform) يغطي Workers وKV وR2 وD1 فقط، ولا يقرأ DNS ولا إعدادات الدومين.
2. **لماذا:** خريطة الـRedirects تحتاج معرفة الموجود: قواعد Redirect وPage Rules، وإعداد SSL، وHSTS، والـCache، والـWAF. ونحتاج سجلات DNS حتى لا نكسر البريد (MX) أو أي نطاق فرعي.
3. **المستوى:** **Read-only API Token فقط.** صلاحيات Read مثل Zone وDNS وZone Settings وPage Rules وFirewall. **لا نطلب أي صلاحية Edit.**
4. **ماذا سنفحص:**
   - سجلات DNS (A/AAAA/CNAME/MX/TXT/CAA).
   - وضع SSL، وHSTS، وHTTP/3، وBrotli.
   - Redirect Rules وPage Rules وCache Rules وWAF.
   - الـWorkers إن وُجدت.
5. **المخاطرة:** لا شيء مع Token للقراءة فقط.
- **ملاحظة تقنية:** الشبكة تحجب `api.cloudflare.com` حاليًا، فيجب إضافته أيضًا إلى الـAllowed domains.
- **كيف تمنحه:**
  - أنشئ Token بصلاحيات Read فقط، وضعه في إعدادات بيئة العمل باسم المتغير `CLOUDFLARE_API_TOKEN_READONLY`، ثم ابدأ جلسة جديدة.
  - **البديل الأسهل:** لقطات شاشة لصفحات DNS وRules وSSL/TLS.

## AC-07 — WordPress (تصدير المحتوى)
1. **الخدمة:** لوحة WordPress للموقع الحالي.
2. **لماذا:** للحصول على كل النصوص، بما فيها المسودات والصفحات غير المربوطة والمقالات الست التي لا نعرف روابطها، وعلى عناوين وأوصاف Yoast، وقائمة الإضافات، وقائمة الـRedirects إن وُجدت.
3. **المستوى:** **ملف تصدير فقط. لا نطلب حساب Admin.**
4. **ماذا سنفحص:**
   - المحتوى الكامل والـSlugs والتواريخ والتصنيفات.
   - روابط الصور.
   - إعدادات SEO لكل صفحة.
5. **المخاطرة:** لا شيء. التصدير لا يغيّر الموقع.
- **كيف تمنحه:**
  - من لوحة WordPress: Tools ← Export ← All content، ثم ارفع الملف هنا أو في Drive.
  - أضف لقطة شاشة لصفحة Plugins.

## AC-08 — Google Drive (متصل أصلًا بهذه الجلسة)
1. **الخدمة:** Google Drive، وهو Connector مرتبط بحسابك.
2. **لماذا:** إذا كان المنيو الرسمي أو الشعار أو الصور أو دليل الهوية موجودة في Drive، نقرأها مباشرة.
3. **المستوى:** Read-only، **وفقط المجلدات أو الملفات التي تسميها**. لن نبحث في بقية Drive.
4. **ماذا سنفحص:** ملفات المنيو، والشعار، والصور، ودليل الهوية.
5. **المخاطرة:**
   - لا تغيير.
   - لن نستخدم أي صورة على الموقع قبل عرضها عليك وتسجيلها في مكتبة الأصول.
- **كيف تمنحه:** أرسل اسم المجلد أو الرابط واكتب "موافق على Drive قراءة فقط لهذا المجلد".

## AC-09 — HubSpot (متصل أصلًا بهذه الجلسة)
1. **الخدمة:** HubSpot، وهو Connector مرتبط بحسابك.
2. **لماذا:** سكربت HubSpot (Portal 148229555) يعمل على كل صفحات الموقع الحالي. نحتاج التأكد أنه حسابكم، وهل توجد Contacts أو Forms أو مشتركون يجب الحفاظ عليهم.
3. **المستوى:** Read-only.
4. **ماذا سنفحص:**
   - رقم الحساب (Portal ID).
   - عدد الـContacts والـForms فقط، بدون قراءة بيانات الأشخاص.
   - هل التتبع مستخدم.
5. **المخاطرة:** لا تغيير. لن نقرأ أو ننسخ بيانات العملاء الشخصية.
- **كيف تمنحه:** اكتب "موافق على HubSpot قراءة فقط".

## AC-10 — PageSpeed Insights / CrUX API Key
1. **الخدمة:** Google PageSpeed Insights API وChrome UX Report API.
2. **لماذا:** لا توجد حاليًا أي بيانات Core Web Vitals (LCP/INP/CLS) للموقع القديم. الحصة المجانية المشتركة في بيئة العمل = 0. نحتاجها كخط أساس نقارن به الموقع الجديد.
3. **المستوى:** Read-only. مفتاح API مقيّد بهاتين الخدمتين فقط.
4. **ماذا سنفحص:**
   - أداء الصفحات الرئيسية على الموبايل والديسكتوب.
   - بيانات المستخدمين الحقيقيين إن وُجدت.
5. **المخاطرة:** لا شيء.
- **كيف تمنحه:**
  - من Google Cloud Console أنشئ API Key مقيّدًا بـ"PageSpeed Insights API" و"Chrome UX Report API".
  - ضعه في إعدادات بيئة العمل باسم المتغير `GOOGLE_PSI_API_KEY`.
  - **بديل:** شغّل الفحص بنفسك على pagespeed.web.dev لصفحات: الرئيسية، والمنيو، والموقع، ودليل إربد، وأرسل الروابط.

## AC-11 — Cloudways
1. **الخدمة:** Cloudways (استضافة الموقع الحالي).
2. **لماذا:** نحتاج معرفة البيئة الحالية: نسخة PHP، وحجم السيرفر ومنطقته، والتطبيقات الأخرى عليه، والـStaging، وجدول الـBackups. هذا لتخطيط الـMigration بأمان.
3. **المستوى:** معلومات ولقطات شاشة فقط. **لا نطلب API Key**، لأن مفتاح Cloudways API يعطي تحكمًا كاملًا بالسيرفر وهذا خطر غير مبرر الآن.
4. **ماذا سنفحص:**
   - إعدادات السيرفر والتطبيق.
   - الـBackups (التكرار ومدة الاحتفاظ).
   - هل يوجد Staging، وهل `shop.shelterjo.com` على نفس السيرفر.
5. **المخاطرة:** لا شيء.
- **كيف تمنحه:** لقطات شاشة لـServer Management وApplication Settings وBackups.

## AC-12 — Semrush (اختياري)
1. **الخدمة:** Semrush. رصيد الـAPI في حسابك وصل إلى صفر أثناء الفحص السابق.
2. **لماذا:** للحصول على ثلاثة أشياء:
   - قائمة النطاقات المرتبطة، وفيها تفاصيل الروابط السبام.
   - تحليل المنافسين العضوي.
   - Site Health Score.
3. **المستوى:** Read-only.
4. **ماذا سنفحص:** Backlinks Referring Domains، وOrganic Competitors (الأردن).
5. **المخاطرة:** لا تغيير. **تكلفة مالية** إذا شحنت الرصيد. يمكنك بدلًا من ذلك تشغيل Site Audit جديد بنفسك من واجهة Semrush، فهذا لا يستهلك API units بنفس الطريقة.
- **قرارك:** شحن الرصيد / تشغيل Audit يدويًا / لا شيء. Search Console قد يغني عن جزء كبير.

## AC-13 — Remote Desktop Commander (بديل فقط)
1. **الخدمة:** Connector متصل يسمح بتنفيذ أوامر على جهازك.
2. **لماذا:** بديل فقط إذا لم ترد تعديل إعدادات الشبكة (AC-01). يمكنه قراءة الموقع من جهازك، لأن الموقع غير محجوب هناك.
3. **المستوى:** تنفيذ أوامر على جهازك الشخصي. حتى لو كانت أوامر قراءة فقط، فهو وصول واسع.
4. **ماذا سنفحص:** نفس AC-01.
5. **المخاطرة:** أعلى من AC-01 لأنه يعمل على جهازك. **لا نوصي به** ما دام AC-01 ممكنًا.
- **الحالة:** لن نستخدمه إلا بطلب صريح منك.

## خدمات لا نحتاجها الآن
- **Meta Business Suite / Facebook / Instagram:** نحتاج روابط الحسابات فقط (R2-09). الـPixel يُبحث في مرحلة Analytics.
- **WordPress.com Connector:** الموقع على Cloudways، وليس على WordPress.com، فلا علاقة له.
- **Gmail / Calendar / Notion / Make / n8n / Supabase:** غير مطلوبة لمرحلة الاكتشاف. Supabase وn8n قد نحتاجهما لاحقًا إذا اخترت أن تكون بيانات المنيو والفروع مصدرًا موحدًا للبوت (R5-06).
