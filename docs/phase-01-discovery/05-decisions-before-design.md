## P0 — تعطل الـInformation Architecture (يجب حسمها أولًا)

### DB-01 — الحقائق التأسيسية للعلامة — ✅ حُسمت (D-007، D-008، D-009)

### DB-02 — اللغة الافتراضية واستراتيجية الـURL اللغوية

> **تحديث بعد R1:** ردودك (جاهزية عالمية + دومين عالمي محتمل لاحقًا) غيّرت المقارنة. أضفنا بُعد **السوق/الدولة** وبُعد **نقل الدومين**، والخيارات المحدّثة في [`09-architecture-options-after-r1.md`](09-architecture-options-after-r1.md) (AR-01). **توصيتنا الآن: Option C هناك.** الجدول أدناه هو النسخة الأولى للمرجع فقط.

| | Option A — العربية على الجذر + `/en/` | Option B — `/ar/` و`/en/` كلاهما Prefixed | Option C — الإنجليزية على الجذر + `/ar/` |
|---|---|---|---|
| مثال | `/menu` · `/en/menu` | `/ar/menu` · `/en/menu` | `/menu` · `/ar/menu` |
| UX Impact | الزائر المحلي (الأغلبية عربية) يصل مباشرة بدون خطوة إضافية | الجذر `/` يحتاج اختيار لغة أو Redirect تلقائي (قد يخطئ ويزعج) | الزائر المحلي يحتاج تبديل لغة |
| SEO Impact | يحافظ على قوة الصفحة الرئيسية الحالية العربية؛ hreflang `ar` / `en` + `x-default=/` | تماثل كامل؛ لكن الجذر يصبح Redirect ويُفقد جزء من الوضوح | ينقل الـequity العربية لمسار جديد — مخاطرة أعلى |
| Performance | بدون Redirect إضافي | Redirect على الجذر (زمن إضافي) | بدون Redirect |
| Scalability (Global) | جيد؛ إضافة لغات لاحقًا كـ`/fr/`… ممكنة | الأفضل نظريًا لتعدد اللغات | جيد عالميًا، ضعيف محليًا |
| Maintenance | بسيط | متوسط | بسيط |
| Mobile Usability | ممتاز | خطوة إضافية عند أول زيارة | خطوة إضافية لأغلب الزوار |

**التوصية المبدئية:** Option A — لأن السوق الحالي عربي أولًا والصفحة الرئيسية الحالية تحمل الترتيب. الجغرافيا (دولة/مدينة/فرع) تكون داخل هيكل الفروع وليس في بادئة اللغة.

### DB-03 — لغة الـSlugs

| | Option A — Slugs لاتينية لكل اللغات | Option B — Slugs عربية للصفحات العربية |
|---|---|---|
| مثال | `/menu` · `/locations` · `/en/menu` | `/المنيو` · `/الفروع` |
| UX | قصيرة، تُقرأ وتُنسخ وتُشارك بدون تشويه | تظهر مشفرة `%D8%...` عند النسخ والمشاركة |
| SEO | Google يعتمد على العنوان والمحتوى؛ أثر الـslug العربي محدود | ميزة طفيفة في الـSERP العربي فقط |
| Maintenance | URL واحد منطقي لكل صفحة في اللغتين | صعب الإدارة مع التوسع |

**التوصية المبدئية:** Option A + `301` من كل الـslugs العربية الحالية التي تحمل ترتيب أو روابط.

### DB-04 — الصفحات التي ستبقى من الموقع القديم (قرارات تجارية)
الصفحات الحالية التي تحتاج قرار تجاري وليس تقني فقط — انظر [`02-url-inventory-and-migration-seed.md`](02-url-inventory-and-migration-seed.md):
- صفحة **الامتياز التجاري (Franchise)** — هل SHELTER يمنح امتيازًا فعلًا؟ (VQ-04)
- صفحة **التوظيف (Careers)** — هل نريد قسم توظيف دائم؟ وما البيانات المسموح جمعها؟ (VQ-05)
- مقالة **"دليل كافيهات إربد 2026"** — أعلى صفحة جالبة للزيارات العضوية حاليًا (#4 لـ"كافيهات اربد")؛ هل نبقيها وبأي صيغة؟
- صفحة **فرع سيتي سنتر** و**صفحة الدرايف ثرو** — هل هما "Shelter Coffee House" و"Shelter Coffee Drive"؟ (VQ-02)
- صفحة **"عائلة شلتر" (الفريق)** — هل نعرض أسماء وصور الفريق؟ (VQ-19)
- صفحة **النشرة البريدية** — هل نريد نشرة/قائمة ولاء؟ (VQ-26)
- **حجز الطاولات والحفلات وأعياد الميلاد** — صفحة/نموذج أم زر اتصال فقط؟ (VQ-06)
- **الرعايات والفعاليات** — قسم مستقل برقم 0799530383؟ (VQ-07)

### DB-11 — الـHost الرسمي: `www.shelterjo.com` أم `shelterjo.com`
حاليًا الجذر بدون `www` يعيد التوجيه (غالبًا إلى `www`)، لكن **أغلب الروابط الخارجية ورابط الـKnowledge Panel في Google تشير إلى النسخة بدون `www`**، والنسختان مفهرستان لبعض الصفحات.
**التوصية المبدئية:** إبقاء `https://www.shelterjo.com` كـHost رسمي (هو المستخدم في كل مكان الآن)، مع 301 دائم من الجذر، وتحديث رابط الموقع في Google Business Profile إلى `www`. القرار ينفَّذ في Cloudflare لاحقًا — **بموافقتك فقط**.

### DB-12 — `shop.shelterjo.com`
نطاق فرعي مفهرس وغرضه غير معروف (VQ-03). نحتاج: هل هو حي؟ هل يُستخدم للطلب؟ هل نغلقه أو نحوله أو نبقيه؟ الموقع الحالي **ليس E-Commerce** حسب تعليماتك، فهذا يؤثر على الـCTA الرئيسي (اطلب عبر Talabat؟ اتصل؟ اتجاهات؟).

## P1 — قبل الـWireframes

### DB-05 — نموذج الـNavigation على الموبايل

| | Option A — Top Header + Bottom Action Bar | Option B — Top Sticky Header باختصارات ظاهرة | Option C — Hamburger كامل |
|---|---|---|---|
| الشكل | أعلى: Logo + اللغة. أسفل ثابت: المنيو · الفروع · اتصال/اتجاهات · المزيد | Logo + [المنيو] [الفروع] ظاهرين + اللغة + ☰ للباقي | Logo + ☰ |
| UX | الأفضل لإبهام اليد الواحدة؛ يشبه التطبيقات | واضح ومألوف؛ أهم وجهتين دائمًا ظاهرتين | يخفي أهم المعلومات — يتعارض مع طلبك |
| Mobile | يحجز ~56px من الشاشة؛ يحتاج تجربة مع شريط Safari السفلي | لا يحجز أسفل الشاشة | الأنظف بصريًا فقط |
| SEO | محايد (روابط حقيقية) | محايد | الروابط مخفية لكنها موجودة |
| Maintenance | متوسط | بسيط | بسيط |

**التوصية المبدئية:** Option B كأساس، مع **Contextual Sticky Action** فقط في صفحات محددة (مثلًا زر "الاتجاهات / اتصال" في صفحة الفرع). نختبر Option A في الـPrototype قبل الاعتماد.

### DB-06 — بنية المنيو

| | Option A — صفحة واحدة `/menu` | Option B — صفحات لكل Category ولكل منتج | Option C — Hybrid |
|---|---|---|---|
| الشكل | كل المنتجات في صفحة، Categories لاصقة + Search، التفاصيل في Drawer بدون URL | `/menu/hot-coffee/` و`/menu/hot-coffee/spanish-latte/` | `/menu` سريعة بالكامل + URL مستقل فقط للمنتجات المميزة (Signature / V60 / Seasonal) يفتح كـDrawer مع Deep Link |
| UX | الأسرع للتصفح | تنقلات كثيرة وتحميل صفحات | سرعة A + مشاركة رابط منتج |
| SEO | صفحة واحدة قوية؛ لا ترتيب لمنتجات فردية | أكبر عدد صفحات لكن خطر Thin Content | صفحة منيو قوية + صفحات منتجات ذات قيمة فقط |
| Performance | يحتاج Lazy Loading ذكي للصور | خفيف لكل صفحة | الأفضل توازنًا |
| Scalability | فروع بمنيو مختلف تحتاج فلتر | جيد | جيد (فلتر فرع/دولة لاحقًا) |

**التوصية المبدئية:** Option C. يعتمد على حجم المنيو الرسمي الذي سترسله.

### DB-07 — بنية الفروع (Country → City → Branch)

| | Option A — Flat | Option B — Hierarchical | Option C — Country Prefix على الجذر |
|---|---|---|---|
| مثال | `/locations/irbid-drive-thru/` | `/locations/jordan/irbid/drive-thru/` | `/jo/irbid/drive-thru/` |
| UX | قصير وواضح | Breadcrumb طبيعي (الأردن › إربد › الفرع) | مربك مع بادئة اللغة `/en/jo/...` |
| SEO / Local SEO | جيد | الأقوى لاحقًا: صفحة مدينة تخدم "كافيهات/قهوة مختصة في إربد" | جيد للـInternational لكن معقد |
| Scalability | تصادم أسماء مع التوسع | الأفضل لتعدد الدول والمدن | جيد |
| Thin-content risk | لا | صفحة دولة/مدينة بفرعين فقط قد تكون رقيقة — الحل: تفعيلها تدريجيًا | متوسط |

**التوصية المبدئية:** Option B مع **Progressive Activation**: صفحة الدولة/المدينة لا تُنشر مستقلة إلا عندما يكون لها محتوى حقيقي (أكثر من فرع أو مدينة).

## P2 — تُحسم في مراحلها، لكن نذكرها الآن لأنها تؤثر على الـArchitecture

### DB-08 — المنصة / الـCMS (يُحسم في Technical Architecture بعد اعتماد الـIA)
متطلباتك (Roles، Audit Log، Revisions، Scheduling تلقائي للحملات، Preview موبايل/ديسكتوب، Design Lock، تعدد لغات، Redirect Manager، SEO Health) تحدد المنصة. الخيارات المرشحة للدراسة لاحقًا:
- **A:** WordPress بثيم مخصص (Block Theme مقفل) على Cloudways.
- **B:** WordPress كـHeadless CMS على Cloudways + واجهة Static/Edge (مثل Astro) عبر Cloudflare.
- **C:** Headless CMS حديث (مثل Sanity أو Payload) + واجهة Astro/Next.
لن نختار الآن. سنقارنها بجدول كامل (Editor UX, Performance, Motion, SEO, Security, Cost, Maintenance) بعد اعتماد الـSitemap.

### DB-09 — اسم ومسار قسم المعرفة
`/blog/` (يحافظ على الـURL الحالي) أم `/coffee/` أو `/learn/` كـCoffee Knowledge Hub بعناقيد مواضيع؟ يُحسم في Stage 6 (Blog).

### DB-10 — عرض الأسعار في المنيو
هل تُعرض الأسعار؟ هل تختلف بين الفروع؟ (يؤثر على الـData Model وعلى تحديث المحتوى). الأسعار القديمة متعارضة (VQ-16).

### DB-13 — الروابط الخارجية السبام (Backlinks)
~144 نطاقًا بنصوص "PBN / buy backlinks" ظهرت يوليو–سبتمبر 2026. نحتاج معرفة: هل تم شراء خدمة روابط؟ القرار (Disavow أو تجاهل) يُتخذ بعد فتح Google Search Console — **لا إجراء الآن**.

### DB-14 — HubSpot و Newsletter
سكربت HubSpot (Portal 148229555) وإضافة Newsletter يعملان على كل الصفحات. هل نحتفظ بهما؟ هل توجد بيانات مشتركين/Contacts يجب نقلها؟ يؤثر على الأداء والخصوصية (VQ-26).
