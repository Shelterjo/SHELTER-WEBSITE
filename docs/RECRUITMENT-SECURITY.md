# RECRUITMENT SECURITY & PRIVACY

> **الحالة:** `DRAFT — PENDING OWNER ARCHITECTURE CHECK` · **آخر تحديث:** 2026-10-01
> **المصدر:** M28 §16–§20، §24، §27، §52، §56، §57، §60–§63، §71 — `OWNER APPROVED`.
> **القرارات التقنية هنا** (طريقة التنفيذ) يتخذها Claude ويوثقها حسب M28 §78.
> **أي خدمة خارجية:** لا تُستخدم بلا موافقة مسبقة (§10).

## 1. نموذج التهديد (مختصر)
| الأصل | التهديد | الحماية الأساسية |
|---|---|---|
| بيانات المتقدمين (هاتف، بريد، تاريخ ميلاد، جنسية) | تسريب، وصول غير مصرح، Enumeration عبر صفحة المتابعة | صلاحية Owner Server-side · لا PII في Analytics أو Logs · حماية صفحة المتابعة (§7) |
| الرقم الوطني / رقم الوثيقة | تسريب قاعدة البيانات أو النسخ | تشفير على مستوى التطبيق + Blind index + إخفاء + Audit عند الإظهار (§5) |
| السير الذاتية والمرفقات | رابط عام، ملف خبيث، تنفيذ كود، XSS داخل الـDashboard | تخزين خاص خارج الويب · فحص Signature · منع الأنواع الخطرة · Download فقط بلا تنفيذ (§3، §4) |
| النموذج العام | سبام، إغراق، رفع ضخم، Replay، CSRF | Rate limit · Honeypot · زمن أدنى · Idempotency · CSRF · حدود حجم (§6) |
| الـDashboard | وصول بالرابط المباشر أو API · جلسة منتهية · مستخدم غير Owner | Deny by default · فحص الدور في كل Endpoint (`RECRUITMENT-PERMISSIONS.md`) |

## 2. خط سير الرفع (Progressive)
1. يُرفع كل ملف **فورًا عند اختياره** إلى `POST /careers/uploads`، مع `upload_session_id` وCSRF، وتظهر نسبة التقدم.
2. **Server-side:**
   - تحقق الحجم مقابل الحد التقني (`CLOUDWAYS-RECRUITMENT-ARCHITECTURE.md` §4).
   - Rate limit.
   - تنظيف الاسم.
   - فحص الامتداد + الـMIME + **Magic bytes**.
   - رفض الأنواع الخطرة.
   - حساب `sha256`.
   - حفظ باسم عشوائي في `private_html/recruitment/tmp/` (حجر مؤقت).
3. **اكتشاف الـCV** يعمل بشكل غير متزامن، ولا يوقف الصفحة (§8).
4. **عند Submit:**
   - تُنقل الملفات من `tmp/` إلى `recruitment/YYYY/MM/` وتُربط بالطلب.
   - **فشل ملف واحد لا يمسح بقية الملفات ولا مدخلات النموذج** (M28 §69).
5. **المسودات غير المرسلة** تُحذف بعد 24 ساعة.

## 3. سياسة أنواع الملفات (M28 §17)
**قرار الـOwner:**
- لا يُحصر المستخدم بـPDF/DOC/DOCX.
- تُمنع الأنواع الخطرة.
- **لا يُعتمد على الامتداد وحده.**

**التنفيذ (قرار تقني):** يُقبل الملف إذا انتمى بـ**التوقيع الفعلي** لإحدى العائلات الآمنة التالية، ورُفض كل ما عداها.

| العائلة المقبولة | أمثلة | الفحص |
|---|---|---|
| PDF | `.pdf` | يبدأ بـ`%PDF-`. يُرفض إذا احتوى JavaScript أو Launch actions، **إن أمكن فحصه محليًا** |
| Word / مستندات | `.doc` `.docx` `.odt` `.rtf` | OLE2 أو ZIP بهيكل OOXML أو ODF صحيح. **تُرفض الملفات بماكرو** (`.docm`، و`vbaProject.bin` داخل ZIP) |
| جداول | `.xls` `.xlsx` `.ods` `.csv` | نفس الفحص. **`.xlsm` مرفوض** |
| عروض | `.ppt` `.pptx` `.odp` | نفس الفحص. **`.pptm` مرفوض** |
| نص | `.txt` | UTF-8/ASCII بلا بايتات ثنائية |
| صور | `.jpg` `.jpeg` `.png` `.webp` `.heic` `.gif` `.tif` `.bmp` | توقيع الصورة. **المعاينة في الـDashboard من نسخة مُعاد ترميزها**، لا من الملف الأصلي |

**مرفوض دائمًا** (حتى لو غُيّر الامتداد):
1. **ملفات تنفيذية:** `.exe` `.dll` `.msi` `.com` `.scr` `.bat` `.cmd` `.ps1` `.vbs` `.jar` `.apk` `.app` `.dmg` `.sh` `.bin` (+ توقيعا MZ وELF).
2. **ملفات تُنفذ على السيرفر:** `.php` `.phtml` `.phar` `.py` `.pl` `.cgi` `.asp(x)` `.jsp`.
3. **ملفات سكربت:** `.js` `.mjs` `.html` `.htm` `.svg` `.xml` `.xhtml` `.hta`.
4. **مستندات بماكرو:** `.docm` `.xlsm` `.pptm`.
5. **ملفات مضغوطة:** `.zip` `.rar` `.7z` `.tar` `.gz` `.iso`.

> ⚠️ **قرار أمني يُبلّغ للـOwner (لا يعيد فتح قراره):** الملفات المضغوطة مرفوضة.
> - **السبب:** قد تخفي ملفات تنفيذية أو "Zip bombs"، ولا يمكن فحصها بأمان دون فك ضغطها على السيرفر.
> - **البديل:** المتقدم يرفع الملفات منفردة، ولا حد تجاري على عددها.
> - **ملاحظة:** ملفات Office الحديثة ZIP داخليًا، لكنها تُقبل بعد التحقق من بنيتها، مع حد لحجمها بعد الفك.

**تنظيف اسم الملف:**
- يُحفظ الاسم الأصلي كـMetadata بعد إزالة محارف التحكم و`../` و`\`، وقصّه إلى 255.
- **التخزين** باسم عشوائي (128-bit) بلا امتداد قابل للتنفيذ.
- **منع Path traversal:** المسار يُبنى من `storage_key` فقط.

## 4. التخزين والتنزيل
1. **مكان التخزين:** `private_html/recruitment/` خارج `public_html`، فلا يوجد أي URL عام.
2. **صلاحيات الملفات:** `0640`، والمجلدات `0750`، ولا صلاحية تنفيذ.
3. **التنزيل:** `GET /owner/recruitment/attachments/{id}/download`.
   - فحص جلسة Owner في كل طلب.
   - رابط مؤقت موقّع (HMAC، ≤ 60 ثانية، مربوط بالجلسة) إن احتاجت الواجهة رابطًا.
4. **ترويسات الاستجابة:**
   - `Content-Disposition: attachment; filename*=UTF-8''…`
   - `X-Content-Type-Options: nosniff`
   - `Content-Security-Policy: sandbox; default-src 'none'`
   - `Cache-Control: no-store`
   - `Content-Type` من `detected_mime` لا من المتصفح.
5. **المعاينة داخل الـDashboard:**
   - **الصور:** نسخة مُعاد ترميزها (PNG/WebP) فقط.
   - **PDF:** في نافذة `sandbox` بلا سكربت، أو تنزيل.
   - **HTML وSVG لا يصلان أصلًا** (مرفوضة في §3).
6. **فحص الفيروسات:** الخوادم المُدارة في Cloudways غالبًا لا تسمح بتثبيت ClamAV بلا Root، ويُتحقق في Audit A-11.
   - **إن لم يتوفر محليًا:** تعتمد الحماية على المنع الصارم (§3)، وعدم التنفيذ، والتنزيل كمرفق، و`scan_status = scan_unavailable`.
   - **أي ماسح خارجي:** يُعرض على الـOwner أولًا (§10).

## 5. الرقم الوطني ووثيقة الهوية (M28 §27)
| الإجراء | التنفيذ |
|---|---|
| التشفير | **AES-256-GCM** على مستوى التطبيق. Nonce عشوائي 96-bit لكل قيمة، و`key_version` للتدوير |
| المفاتيح | `RECRUITMENT_ID_ENC_KEY` و`RECRUITMENT_ID_HMAC_KEY`، 32 بايت لكل منهما.<br>- **في بيئة السيرفر أو ملف داخل `private_html`.**<br>- ليست في Git ولا في الـFrontend ولا في النسخ المرسلة بالمحادثة.<br>- نسخة احتياطية آمنة للمفاتيح يحتفظ بها الـOwner، لأن **فقدانها = فقدان القدرة على قراءة الأرقام** |
| اكتشاف التكرار | `id_blind_index = HMAC-SHA256(HMAC_KEY, normalized_id)`. يُبحث به بلا فك تشفير |
| العرض | القوائم والجداول والتصدير الافتراضي: `********1234`.<br>"إظهار" في صفحة الطلب: **Owner فقط** + إعادة تأكيد الهوية إذا مضى على الدخول أكثر من 10 دقائق + سجل `identity.revealed` |
| ممنوع | إرسالها لـGA4/GTM أو أي Analytics · كتابتها في Logs أو رسائل الخطأ · وضعها في URL أو Query string |

## 6. حماية النموذج العام (M28 §61)
| الحماية | التنفيذ |
|---|---|
| CSRF | Token مرتبط بالجلسة و`upload_session_id` |
| التحقق | **كل القواعد Server-side** (الحقول الإلزامية، الشرطية، التاريخ، الكبيسة، الراتب، الموافقة، الـCV الأساسي). الواجهة للتجربة فقط |
| Rate limiting (قيم تقنية أولية تُضبط بعد المراقبة) | لكل IP:<br>- **إرسال:** 5 طلبات/ساعة، و20/يوم.<br>- **رفع:** 60 ملفًا/ساعة.<br>إضافة: **حد إغراق تقني قابل للضبط** لنفس الهاتف المطبّع (مبدئيًا 3 خلال 24 ساعة).<br>- **ليس منعًا للتقديم المتكرر** (المسموح بقرار الـOwner، M28 §26).<br>- عند الوصول للحد: رسالة "يمكنك إرسال طلب جديد لاحقًا" بلا رفض دائم. |
| Bot/Spam | Honeypot مخفي + زمن تعبئة أدنى (مثلًا ≥ 8 ثوانٍ) + Rate limit.<br>**لا CAPTCHA خارجي** إلا بموافقة إذا ظهر سبام فعلي |
| الإرسال المكرر / Replay | `idempotency_key` فريد لكل نموذج، يُرفض الإرسال الثاني ويعيد نفس رقم الطلب. وتعطيل زر الإرسال أثناء المعالجة |
| قاعدة البيانات | Parameterized queries / ORM فقط |
| حدود المدخلات | طول أقصى لكل حقل (الاسم 150، المنطقة 120، الوظيفة 150، الجنسية 80، الملاحظات 3000) وحد لحجم الطلب |
| XSS | ترميز المخرجات في كل مكان، وCSP صارمة في الـDashboard، ولا HTML من المتقدم يُعرض كـHTML |
| رسائل الخطأ | عربية وعامة، بلا تفاصيل تقنية أو Stack traces |

## 7. صفحة متابعة الطلب (M28 §24، §62)
1. **الدخول:** رقم الطلب + رقم الهاتف فقط، عبر POST (لا شيء في الـURL).
2. **المطابقة:** رقم الطلب كما هو + `phone_normalized` بعد تطبيع المدخل.
3. **الاستجابة عند الفشل:** موحدة دائمًا "تعذر العثور على الطلب. تحقق من البيانات وحاول مجددًا"، بنفس الزمن تقريبًا، ولا تفرق بين "رقم غير موجود" و"هاتف خاطئ".
4. **الحدود والتهدئة:**
   - Rate limit: 5 محاولات/15 دقيقة لكل IP، و10 محاولات/يوم لكل رقم طلب.
   - **تهدئة متصاعدة** بعدها (1 ← 5 ← 30 دقيقة).
5. **ما يُعرض:** **الحالة العامة فقط** (`RECRUITMENT-PUBLIC-STATUS-MAPPING.md`). لا CV ولا بريد ولا هوية ولا ملاحظات ولا تفاصيل مقابلة.

## 8. اكتشاف السيرة الذاتية محليًا (M28 §19)
**القاعدة:** بلا AI خارجي وبلا SaaS، وبحساب نقاط حتمي على السيرفر.

| الإشارة | النقاط |
|---|---|
| اسم الملف يحتوي `cv` · `resume` · `résumé` · `curriculum` · `vitae` · `سيرة` · `السيرة الذاتية` | +50 |
| النص المستخرج (PDF/DOCX/ODT/TXT، بحدود حجم وزمن) يحتوي عناوين مثل Education/Experience/Skills/Objective أو التعليم/الخبرات/المهارات/المؤهلات | +15 لكل مجموعة (حد 30) |
| بريد أو هاتف في أول الصفحة | +10 |
| عدد الصفحات 1–5 | +10 |
| صورة فقط (بلا نص) | 0 نص. يعتمد على الاسم |

**القرار:**
| الحالة | النتيجة |
|---|---|
| ملف مستند واحد فقط مرفوع | `auto_single`: هو الـCV الأساسي، لأن الـCV إلزامي والمرفق الوحيد |
| أعلى ملف ≥ 60 نقطة، ويتفوق على الثاني بـ20 نقطة أو أكثر | `auto_confident` |
| غير ذلك | **لا تخمين:** يُطلب من المتقدم "أي ملف هو السيرة الذاتية؟" |

> **الإرسال لا يكتمل بلا CV أساسي محدد.**

- **استخراج النص:**
  - بأداة محلية (`pdftotext` إن توفرت حسب A-11، أو مكتبة داخل التطبيق).
  - بحد زمن (3 ثوانٍ) وحد حجم.
  - **لا يُنفذ أي محتوى.**
  - إن تعذر الاستخراج تُستخدم إشارة الاسم وحدها.

## 9. الأرشفة والحذف والاحتفاظ
1. **لا حذف تلقائي للطلبات أبدًا.**
2. التنبيه للطلبات القديمة عبر "Last Updated" فقط.
3. **الحذف النهائي:**
   - Owner فقط، من الأرشيف.
   - تأكيد قوي: كتابة رقم الطلب.
   - يحذف كل البيانات والمرفقات والهوية والملاحظات والمقابلات.
   - Tombstone بلا PII (`RECRUITMENT-DATA-MODEL.md` §7).
4. **النسخ الاحتياطية:** تبقى فيها البيانات المحذوفة حتى انتهاء مدة احتفاظ Cloudways، وتُذكر المدة بعد الـAudit.

## 10. الخدمات الخارجية (M28 §71)
**ممنوعة تلقائيًا:**
- Sentry، وماسحات فيروسات خارجية، وخدمة البريد، وSMS، وWhatsApp API.
- التخزين الخارجي، وOCR خارجي، وAI parsing.

**الإجراء:** إن ظهرت حاجة لأي منها، تُعرض أولًا مع:
- السبب.
- البديل المحلي.
- التكلفة.
- أثر الخصوصية.

**لا إرسال بريد ولا واتساب عند التقديم.** إشعار داخل الـDashboard فقط.

## 11. الـAnalytics (M28 §57)
**الأحداث المسموحة فقط:**
- `careers_page_view`
- `application_started`
- `application_submitted`
- `application_error`

**المعاملات (بلا PII):**
- `form_variant`
- `step` (إن وُجدت خطوات)
- `error_type`: قيمة من قائمة ثابتة مثل `validation` · `upload_rejected` · `upload_too_large` · `network` · `server` · `cv_required`
- `file_count_bucket`: `1` · `2-3` · `4+`

**ممنوع إرساله:**
- الاسم، والهاتف، والبريد.
- الرقم الوطني أو رقم الوثيقة.
- اسم أي ملف.
- الملاحظات.
- نص الوظيفة.
- رقم الطلب.

> هذه الأحداث تُضاف إلى قاموس الأحداث العام للاعتماد (PO-043).

## 12. ملاحظة قانونية (مخاطرة، وليست إعادة فتح لقرار)
- النموذج يجمع بيانات شخصية: رقم وطني، جنسية، حالة اجتماعية، تاريخ ميلاد.
- **ما يغطي ذلك الآن:** الموافقة المعتمدة (M28 §21) وحمايات هذا الملف.
- **المطلوب لاحقًا:** يُراجع ضمن سياسة الخصوصية والمراجعة القانونية (PO-019) قبل الإطلاق، للتأكد من الالتزام بقانون حماية البيانات الشخصية الأردني.
- **لا تغيير على الحقول المعتمدة.**
