## 1. القاعدة
- **مكان واحد للكود:** `app/Services/Applications/Forms` + مكونات `x-ui.field` و`x-ui.form` المشتركة.
- **كل نموذج = إعداد**، لا كود مكرر: قواعد التحقق · الجدول الخاص · البادئة · حدود المعدل · زمن التعبئة الأدنى.
- **التحقق كله في الخادم.** تحقق المتصفح للتجربة فقط.
- **رفض الحقول غير المعرّفة** في الطلب (FRAN-049).

## 2. المسار (M35 §11)
```
USER SUBMITS ── الزر يُعطّل + "جاري الإرسال…" · المفتاح idempotency_key مخفي في النموذج
   ▼
SERVER VALIDATION ── CSRF · Honeypot · زمن التعبئة · Rate limit · قواعد الحقول
   ▼
DATABASE SAVE ── (1) حجز المفتاح: idempotency_keys = PROCESSING (فهرس فريد، كتابة مستقلة قصيرة)
   │   (2) معاملة واحدة: reference_sequences (قفل صفّي) → applications + جدول النوع → audit_logs
   │       → idempotency_keys = COMPLETED + المرجع
   │   أي استثناء ← Rollback للمعاملة + المفتاح = FAILED
   ▼
CONFIRM SAVE ── COMMIT نجح + إعادة قراءة السطر
   ▼
RETURN SUCCESS ── 303 إلى صفحة نجاح برابط موقّع (PRG) تعرض الرقم المرجعي
   ▼ (بعد الـCOMMIT فقط)
signals: EVENT ACTION_REQUIRED · حدث التحليلات يُرسل من صفحة النجاح فقط
```
- **لا نجاح قبل الـCOMMIT أبدًا.**
- **الإشعار يُرسل `afterCommit`:** فشله لا يلغي طلبًا محفوظًا، ويُسجّل إشارة.
- **النماذج تعمل بلا JavaScript:** POST عادي + PRG. JavaScript يحسّن التجربة فقط (أخطاء فورية، بلا إعادة تحميل). الاستثناء: الرفع التدريجي للملفات في التوظيف والفرنشايز حسب تصميمه.

## 3. منع التكرار (Idempotency — M35 §13)
- **المفتاح:** UUID يولّده الخادم عند عرض النموذج، **مرة لكل عرض**، ويُعاد إرساله كما هو عند إعادة المحاولة.
- **`idempotency_keys`:** `key` (فريد) · `scope` (اسم النموذج) · `status` (PROCESSING / COMPLETED / FAILED) · `request_hash` (sha256 للحمولة المطبّعة، **بلا PII خام**) · `result_ref` · `created_at` · `expires_at` (24 ساعة).

| الحالة | السلوك |
|---|---|
| مفتاح جديد | يُنشأ PROCESSING ثم يكمل المسار |
| نفس المفتاح وهو PROCESSING (ضغطتان) | انتظار حتى 5 ثوانٍ، ثم نفس النتيجة، أو `202` "طلبك قيد الحفظ" |
| نفس المفتاح وهو COMPLETED | **نفس صفحة النجاح ونفس الرقم المرجعي**، بلا سطر جديد |
| نفس المفتاح بحمولة مختلفة | `422` "تغيّرت البيانات — أعد الإرسال" ← مفتاح جديد |
| المفتاح FAILED (فشل قبل الـCOMMIT) | يُسمح بإعادة المحاولة بنفس المفتاح |

- **لا منع للطلبات المستقلة الصحيحة:** عرض جديد للنموذج = مفتاح جديد = طلب جديد (M35 §13).
  - التقديم المتكرر للتوظيف مسموح (CAREERS-044). تكرار الفرنشايز يُكشف ولا يُمنع (FRAN-060).
- **المفاتيح المنتهية** تُحذف يوميًا بمهمة مسجلة في `scheduled_job_runs`.
- **عمود `job_applications.idempotency_key`** (RECRUITMENT-DATA-MODEL) يبقى مرجعًا. الآلية المشتركة هي هذا الجدول.

## 4. الحماية من السبام (بلا CAPTCHA مدفوع)
| الطبقة | القاعدة |
|---|---|
| **Honeypot** | حقل مخفي بصريًا (`aria-hidden` · `tabindex=-1` · `autocomplete=off`). إن امتلأ ← رسالة عامة "تعذر الإرسال، حاول مجددًا"، **بلا حفظ وبلا نجاح وهمي**، وعدّاد داخلي |
| **زمن التعبئة** | طابع زمني موقّع (HMAC) في النموذج. أقل من **3 ثوانٍ** (INQ · FR · Feedback) أو **8 ثوانٍ** (JOB — RECRUITMENT-SECURITY §6) ← رفض برسالة عامة. أقدم من 24 ساعة ← "انتهت صلاحية الصفحة" والمدخلات باقية |
| **Rate limit** | بمفتاح HMAC للـIP في الـCache، **لا يُخزن**. INQ وFR: 5/ساعة و20/يوم. Feedback: 5 كل 10 دقائق و60/يوم (قد يشترك زبائن الفرع في شبكة واحدة). JOB: حسب RECRUITMENT-SECURITY §6 (ومنه الرفع 60 ملفًا/ساعة). التجاوز ← `429` والمدخلات باقية |
| **CSRF** | Laravel. انتهاء الجلسة (`419`) ← نفس النموذج بمدخلاته ورسالة واضحة |
| **حدود المدخلات** | طول أقصى لكل حقل، وحد لحجم الطلب. كل المدخلات تُعرض Escaped في الـDashboard |

**CAPTCHA خارجي = خيار فقط، إن ظهر سبام فعلي (CAREERS-081، FRAN-049):**

| الخدمة | الغرض | الاستخدام المتوقع | التكلفة / الحصة | البديل المجاني |
|---|---|---|---|---|
| Cloudflare Turnstile | تمييز البشر من البوتات | كل إرسال نموذج عام | مجاني حسب شروط Cloudflare الحالية (**تُتحقق وقت الطلب**)، لكنه سكربت طرف ثالث (PERF-011، الخصوصية) | Honeypot + زمن التعبئة + Rate limit (V1) |

## 5. الحفاظ على المدخلات وإعادة المحاولة الآمنة (M35 §12)
- **خطأ تحقق:** إعادة النموذج بكل المدخلات، ما عدا الملفات والـHoneypot.
  - ملخص أخطاء أعلى النموذج بـ`role="alert"` ونقل التركيز إليه.
  - كل خطأ مرتبط بحقله (`aria-describedby`).
- **فشل الشبكة:** المدخلات تبقى في الصفحة (الذاكرة فقط). زر "أعد المحاولة" يرسل **نفس المفتاح**، فإن كان الطلب قد حُفظ يعود بنفس الرقم.
- **لا PII في `localStorage` أو `sessionStorage`.**
- **الملفات (JOB · FR):** رفع تدريجي عبر خط الرفع الواحد (RECRUITMENT-SECURITY §2–§4، SECURITY-CENTER §5).
  - فشل ملف لا يمسح بقية الملفات ولا المدخلات.
  - المسودات المؤقتة تُحذف بعد 24 ساعة.
  - **INQ بلا مرفقات في V1.**
- **السجل:** خطأ الخادم يُسجّل باسم النموذج والمسار ونوع الاستثناء فقط، **بلا جسم الطلب**، مع منظّف PII (هواتف، بريد، أرقام هوية — PRIV-013).

## 9. مكانه في الـDashboard
