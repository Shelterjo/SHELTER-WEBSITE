# CHANGE IMPACT — ماذا سيتغيّر قبل النشر؟

| البند | القيمة |
|---|---|
| **الغرض** | قبل نشر أي تغيير مركزي يرى الـOwner **أين ستظهر القيمة الجديدة**: الصفحات، والـSchema، وGoogle Business Profile، والمنيو، والبحث، والـCache. **لا تغيير واسع صامت** |
| **الحالة** | `SPEC — READY FOR BUILD` · التنفيذ: `NOT STARTED` |
| **مرحلة البناء (M36 §6)** | **PHASE 1–2:** محلّل الأثر (نفس محلّل وسوم الـCache) · **PHASE 6:** شاشة المعاينة الكاملة (Change Impact Preview) |
| **الأولوية** | P0 (OPS-010) |
| **المتطلبات** | OPS-015 · OPS-012 · OPS-013 (Used In) · OPS-053 (خطوة IMPACT) · MEDIA-013 · SEO-037 · CMS-008 · DEPLOY-012 · AUDIT-001 · AUDIT-006 · AUDIT-009 · M32 §04 · M35 §25 · AC-1 |
| **المراجع الملزمة** | [`PLATFORM-ARCHITECTURE`](../architecture/PLATFORM-ARCHITECTURE.md) §4.2 · [`CACHE-CDN`](CACHE-CDN.md) §3 §5 · [`MASTER-DATA-HUB`](../MASTER-DATA-HUB.md) §4 §10 §11 · [`PUBLISH-GUARD`](PUBLISH-GUARD.md) |
| **اختبار القبول (OPS-003)** | تحكم الـOwner + اتساق البيانات: يعرف أثر قراره قبل أن يحدث |

## 1. المبدأ
- السؤال قبل كل نشر مركزي: **WHAT WILL CHANGE?** ثم: معاينة الأثر ← نشر.
- ينطبق على (M32 §04): الهاتف الرئيسي · الساعات · العنوان · السعر · توفر الصنف · الصورة الرئيسية · الحملة · عنوان SEO · الفئة · الـCTA العام.
- **إلزامي** عندما يظهر الكيان في سطحين أو أكثر، أو في قناة خارجية، أو في Schema. غير ذلك: سطر مختصر "يؤثر على: هذه الصفحة".

## 2. مصدر القائمة: محلّل واحد
**محلّل الأثر** (`app/Services/Core/Impact`) يقرأ **خريطة أثر واحدة** في الكود (`config/impact.php`، بإصدارات Git):

| لكل نوع كيان أو حقل | يعطي |
|---|---|
| الأسطح | المكونات والصفحات AR/EN (Header، Footer، صفحة الفرع…) |
| Schema | كتل JSON-LD المتأثرة |
| القنوات | GBP (حقل آلي أو **يدوي**) · المستقبلية عبر `external_references` |
| المشتقات | فهرس البحث · الـSitemap · روابط hreflang |
| وسوم الـCache | بمفردات [`CACHE-CDN`](CACHE-CDN.md) §3 |

**+ المصادر الديناميكية:** `media_usages` (أين تُستخدم الصورة) · `page_sections.refs` (Tokens تُستخرج عند الحفظ) · علاقة الفئة بمنتجاتها · `experiences.placements` · `channel_overrides` (إن كان لقناة قيمة خاصة معتمدة، تعرض المعاينة أن **هذه القناة لن تتغير**).

**نفس المحلّل يخدم أربعة استخدامات**، فلا يمكن أن يختلف أحدها عن الآخر:
1. شاشة المعاينة.
2. إبطال الـCache بعد النشر (CACHE-CDN §5 "المحلّل").
3. عمود "مستخدمة في" للحقائق ([`FACT-REGISTRY`](FACT-REGISTRY.md) §2).
4. نطاق فحص CI للنصوص الثابتة (OPS-012).

> **لا جدول `usage_edges`** (اقتراح GAP-CLOSURE-PLAN §D مستبدل بالخريطة + `media_usages` + `page_sections.refs`).

## 4. ماذا يرى الـOwner (Wireframe `d-impact`)
1. **"هذا التغيير يؤثر على:"** قائمة مجمعة: الموقع (عربي/إنجليزي) · Schema · Google · البحث. **وسوم الـCache تحت "تفاصيل متقدمة" فقط** (الـOwner لا يرى كلمة Cache).
2. **ما تغيّر:** قبل ← بعد لكل حقل، وعدد الصفحات المتأثرة. تغيير الأسعار الجماعي: عدد المنتجات والقديم والجديد (AUDIT-006).
   - **سبب التغيير:** حقل إلزامي للسعر والساعات والإغلاق (`content_versions.reason` — PLATFORM-ARCHITECTURE §3.1).
3. **معاينة الأثر:** روابط معاينة موقّعة (`noindex`) لكل صفحة متأثرة: عربي/إنجليزي × موبايل/ديسكتوب (CMS-008).
4. **قوة التأكيد حسب الخطورة** (DEPLOY-012): عادي = تأكيد واحد · الإغلاق على Google = كتابة كلمة التأكيد + إعادة تأكيد الهوية.
5. ثم **"متابعة إلى فحص النشر"**.

> **AC-1:** ظهور GBP في هذه المعاينة ثم نشر الـOwner = موافقته على تعديل GBP. **الاسم والعنوان والـPin يبقى يدويًا** دائمًا.

## 5. بعد النشر (M35 §25)
```
نشر ← تحديث Master Data ← content_versions (+ reason) + audit_logs (قائمة الأثر + channels_affected)
   ← إبطال الوسوم + sync_jobs لكل قناة (مربوطة بسطر التدقيق) ← تحقق ← الحالة
```
- **رسالة صريحة، لا نجاح صامت** (MASTER-DATA-HUB §11): "تم تحديث الموقع ✓ · Google Business Profile: فشل التحديث — نعيد المحاولة تلقائيًا [مراجعة]".
- الحالة لكل قناة من `channel_sync_states`. الفشل النهائي ← إشارة HIGH في "يحتاج انتباه".
- سطر التدقيق يحفظ قائمة الأثر كما عُرضت، والقنوات في `channels_affected`، فيجيب لاحقًا عن "ما الذي تغيّر؟ وأين؟" (AUDIT-009).

## 6. البيانات
`config/impact.php` (كود) · `media_usages` · `page_sections.refs` (عمود) · `channel_overrides` · `content_versions` (`reason`) · `audit_logs` (`channels_affected`) · `sync_jobs` · `channel_sync_states` · `signals`. **لا جداول جديدة.**

## 8. مكانه في الـDashboard
- **داخل المحررات**، خطوة قبل فحص النشر. **ليس عنصرًا في القائمة** (OPS-049).
- في **النظام ← سجل التدقيق:** كل تغيير يعرض قائمة أثره. Owner فقط (OPS-050).

## 9. اختبارات القبول
| # | الاختبار | المتوقع |
|---|---|---|
| CI-T1 | فحص ثابت: كل استدعاء `MasterData::…('key')` في القوالب | المفتاح معرّف في الخريطة، وإلا فشل الـCI |
| CI-T2 | تغيير الهاتف الرئيسي | القائمة = الأسطح الموجودة فعلًا في البناء. بعد النشر كل صفحة في القائمة تعرض القيمة الجديدة. **الوسوم المُبطلة = الوسوم المعروضة** (عميل CDN وهمي) |
| CI-T3 | تغيير سعر صنف | الوسوم ⊆ {`prd` · `menu:ar` · `menu:en` · `schema:menu` · `search:ar` · `search:en`}، **ولا Purge شامل** |
| CI-T4 | فشل GBP (Mock 500) | الموقع محدث، والرسالة تذكر الفشل وإعادة المحاولة، وإشارة HIGH بعد استنفاد المحاولات |
| CI-T5 | تغيير العنوان | GBP يظهر **MANUAL ACTION REQUIRED**، ولا طلب كتابة للـAPI |
| CI-T6 | إغلاق مؤقت على Google | يطلب كتابة التأكيد وإعادة تأكيد الهوية، وإلا 403 |
| CI-T7 | سطر التدقيق بعد النشر | يحتوي قائمة الأثر JSON و`channels_affected`. تغيير سعر بلا سبب = رفض |
| CI-T8 | مستخدم غير Owner | 403 على المعاينة والنشر |
| CI-T9 | الشاشة على مصفوفة العروض AR/EN | بلا Overflow، وaxe بلا Serious/Critical |

## 10. ما لا يُفعل
- لا نشر لبيانات مركزية بلا معاينة.
- لا دفع آلي للاسم أو العنوان إلى GBP.
- لا Purge شامل.
- لا تخمين للأثر: الخريطة المعلنة + الاستخدامات المسجلة فقط.
- لا جدول استخدام ثانٍ.
